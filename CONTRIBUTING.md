# Contributing

Thanks for helping. Bug reports, suggestions and new evaluation cases are all welcome.

## Report a problem or suggest something

Use an [issue form](https://github.com/DedSecLabs/gta-sa-openmp-devkit/issues/new/choose):

- [Bug report](https://github.com/DedSecLabs/gta-sa-openmp-devkit/issues/new?template=bug_report.yml): a bundled tool or the skill's instructions misbehave.
- [Feature request](https://github.com/DedSecLabs/gta-sa-openmp-devkit/issues/new?template=feature_request.yml): an improvement you would find useful. Suggestions are not commitments.
- [Evaluation case](https://github.com/DedSecLabs/gta-sa-openmp-devkit/issues/new?template=evaluation_case.yml): a real example of an agent getting GTA SA or open.mp work wrong.

Never attach game files, decompiled scripts, or secrets. Hashes and short excerpts are enough.

## Run the tests

Python 3.12 or newer, standard library only:

```bash
python -m unittest discover -s tests -v
```

CI runs the same command on Linux, Windows and macOS with Python 3.12 and 3.13. All fixtures are generated by
the tests; do not commit game content or real executable fingerprints.

## Pull requests

- Keep a change focused. Add or update a test with a behavior change in a tool.
- The skill is `skills/gta-sa-openmp-devkit/`; `tests/` and `evals/` are not installed for users.
- Add a line to [`CHANGELOG.md`](CHANGELOG.md) only when a release is being prepared. Versions, tags and releases
  are handled by the maintainer (see the README's release note); please do not bump the version in a pull request.
- Use a short Conventional Commits subject, for example `fix(tools): reject empty include folder`.

## Evaluation cases

A case is a prompt where an unaided agent tends to be confidently wrong, plus a rubric. Start by opening an
evaluation case issue so the idea can be checked before you write files. Then add a folder `evals/<case-name>/`
modeled on an existing one, such as [`evals/does-not-invent-native`](evals/does-not-invent-native):

- `prompt.md`: the request given to the agent, with the same front matter as existing cases.
- `place-files.sh`: generates the **synthetic** input files. Nothing in it may be real game content.
- `case.yaml`: the case name and a short `expected_outcome`.
- `graders/NN-check.md`: three or four plain, checkable statements, one per file. Grade the answer's honesty
  and evidence (checked the includes, said "unverified", cited the file), not wording.

A good case is small, offline, deterministic to set up, and has a correct answer you can cite. Results from a
run, if you include them, go in the pull request description; the repository's own
[results](evals/RESULTS.md) are recorded by the maintainer.
